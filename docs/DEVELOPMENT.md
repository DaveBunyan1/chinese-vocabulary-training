# Development guide

Practical notes for working in this monorepo. Architecture and domain detail live in the other `docs/` files; this page is about day-to-day workflow.

## Repository layout

```
backend/     Python package (FastAPI, domain, infrastructure)
frontend/    React + Vite UI
docs/        Architecture, domain model, ADRs, RFCs
```

The backend is an installable package (`chinese-learning`) with a classic hexagonal layout:

```
backend/src/chinese_learning/
├── domain/            # Pure domain – no FastAPI / SQLAlchemy
├── application/       # Use cases
├── infrastructure/    # DB, NLP, telemetry
└── presentation/      # HTTP routers & schemas
```

## Recommended workflows

### Full stack (Docker)

```bash
docker compose up --build
```

| URL | Service |
| --- | --- |
| http://localhost:3000 | Frontend (nginx) |
| http://localhost:8000 | Backend API |
| http://localhost:8000/docs | OpenAPI (Swagger) |
| http://localhost:8000/health | Health probe |

Nginx proxies `/api/` → `backend:8000`. Backend source is bind-mounted for live reload.

### Backend only

```bash
cd backend && python3.14 -m venv .venv && source .venv/bin/activate
cd .. && pip install -e "./backend[dev]"
make db-up
uvicorn chinese_learning.app:app --reload --port 8000
```

### Frontend only (API already running)

```bash
cd frontend && npm install && npm run dev
```

Vite listens on port **3000** and proxies `/api` → `http://localhost:8000` (`frontend/vite.config.ts`).

## Quality gates

```bash
make lint          # Ruff + Mypy (backend)
make test-unit     # Fast unit tests, no Docker
make test-integration
make test          # Full suite

cd frontend && npm run lint && npm run build
```

Pre-commit runs Ruff + Mypy only (see `.pre-commit-config.yml`). Full tests run in CI.

## API conventions

- Public HTTP surface is versioned under **`/api/v1`**.
- OpenAPI is generated by FastAPI at `/docs` and `/redoc`.
- Health: `GET /health` returns `status`, `environment`, and `version`.
- Auth is not implemented yet (single-learner MVP). Add an explicit scheme before exposing the API beyond local/dev.

## Observability

- **Logging:** structlog is configured at startup (`setup_logging`). Development uses a console renderer; non-development uses JSON.
- **OpenTelemetry:** packages are declared in `pyproject.toml` and a metrics import exists in persistence helpers. Full FastAPI auto-instrumentation / exporters are **not** wired yet — treat OTEL as planned, not production-ready.

## Environment

See root `.env.example`. Important variables:

| Variable | Used by |
| --- | --- |
| `DATABASE_URL` | Backend (async SQLAlchemy) |
| `ENVIRONMENT` | Logging style, health payload |
| `LOG_LEVEL` | structlog / stdlib level |
| `VITE_API_BASE_URL` | Optional frontend override (default `/api/v1`) |
